# MMORPG domain context

Use this as a navigation map before designing or modifying gameplay, not as a second specification. [AGENTS.md](AGENTS.md) defines the workflow; [architecture](docs/ARCHITECTURE.md) defines authority; the [Decision Atlas](docs/decisions/atlas.md) records product intent; current source and tests establish what actually runs. `coding-tooling inspect --target <path> --json` retrieves the matching scopes in [.coding-tooling.json](.coding-tooling.json), including related producers and consumers. Multiple scopes can apply. If starting from a feature name rather than a path, use the entry points below.

## Combat and actions

- **Action graph**: [core action.rs](crates/mmorpg-core/src/action.rs) (definitions; `action/validation.rs`, `action/runtime.rs`, `action/inspection.rs` beside it) and [production baseline](crates/mmorpg-core/src/action/baseline.rs) own authored phases, compatibility, interruption, cancellation/follow-up windows, arbitration and movement restrictions where integrated. Read Atlas 5.2.39/41, 5.7–5.9. Distinguish production baseline from validated lab configurations.
- **Basic strike / directed strike / timed swing**: [melee.rs](crates/mmorpg-core/src/melee.rs) executes the Q attack's standing chain, running and jumping strikes (variant, profile, contact, lunge) and holds their canonical pending/recovery/follow-up state; the action graph runs them as `ActionId::BasicMelee` and owns when a press begins, which chain step follows and what a stun does to a wind-up (#1221); [sim-combat melee.rs](crates/sim-combat/src/melee.rs) supplies weapon profiles. [strike.rs](crates/mmorpg-core/src/strike.rs), [swing.rs](crates/mmorpg-core/src/swing.rs), [combo.rs](crates/mmorpg-core/src/combo.rs) and [guard.rs](crates/mmorpg-core/src/guard.rs) implement directed attacks, content-selected timed sweeps/clashes and associated combos/guard. [combat.rs](crates/mmorpg-core/src/combat.rs) coordinates common damage and attack execution. The offense-region report names the running basic strike, its phase and follow-up window.
- **Action Lab**: [scenario guide](docs/SCENARIOS.md) documents the existing playable inspector, A/B recording/replay, and promotion path (#380, #381, #383, #413, #414). [Local host lab](crates/mmorpg-local-host/src/action_lab.rs), [experiments](crates/mmorpg-local-host/src/lab_experiment.rs), [browser dock](web/src/world/action-lab.ts). The lab uses actual core, not another combat engine. Test anchors: [graph](crates/mmorpg-core/tests/combat/action_graph.rs), [windows](crates/mmorpg-core/tests/combat/action_windows.rs), [basic strikes](crates/mmorpg-core/tests/combat/movement_strikes.rs), [timed swings](crates/mmorpg-core/tests/combat/timed_swing.rs), [lab experiments](web/tests/lab-experiment.test.ts).
- **Contact / presentation**: [sim-combat swing.rs](crates/sim-combat/src/swing.rs) supplies hit geometry; zone execution resolves contact and outcomes. [Shared imported clip playback](crates/mmorpg-presentation/src/units/imported/playback.rs) fits clips to authoritative contact time; [effects](crates/mmorpg-presentation/src/units/effects.rs), [contact feedback](crates/mmorpg-presentation/src/units/contact.rs) and [impact cues](crates/mmorpg-client-model/src/impact.rs) present confirmed events. A clip or VFX never decides gameplay. Temporal alignment does not prove spatial weapon/volume alignment. Atlas 6.6, [avatar assets](docs/AVATAR_ASSETS.md), [presentation tests](crates/mmorpg-presentation/tests/units.rs).

## Movement and physics

**Locomotion** means intent, acceleration, jump and traversal, not rendering movement: [sim-movement walk.rs](crates/sim-movement/src/walk.rs), [core zone.rs](crates/mmorpg-core/src/zone.rs) and [stance.rs](crates/mmorpg-core/src/stance.rs) compose the controller velocity in one order (#1226): drive (scaled intent, or a running strike's lunge), then the graph's authored phase movement, then surface grip, then current and follow-up impulse. [Physics adapter](crates/sim-foundation/src/physics.rs) uses Physics Engine in production (Rapier is diagnostic only); [predictor](crates/mmorpg-core/src/prediction.rs) reuses core and reconciles. Atlas 5.9.1–5.9.3; [controls](docs/CONTROLS.md), [physics](docs/PHYSICS_AB.md); [movement](crates/mmorpg-core/tests/world/movement.rs) and [action traversal](crates/mmorpg-core/tests/combat/action_traversal.rs) tests.

## Abilities, progression and equipment

**Ability**: stable ID, typed definition, unlock level and effect in [ability.rs](crates/mmorpg-core/src/ability.rs); [casting.rs](crates/mmorpg-core/src/casting.rs) validates and executes casts, cooldowns and effects; [aura.rs](crates/mmorpg-core/src/aura.rs) owns aura bookkeeping. **Progression**: [progression.rs](crates/mmorpg-core/src/progression.rs) owns level/XP, [mastery.rs](crates/mmorpg-core/src/mastery.rs) weapon proficiency and techniques, [equipment.rs](crates/mmorpg-core/src/equipment.rs) equipment state; [character records](crates/mmorpg-core/src/character.rs) and the existing character store own durable state at their respective boundaries. Extend these before inventing a talent or unlock system. See [progression](docs/PROGRESSION.md), [inventory](docs/INVENTORY.md), Atlas 5.2/5.3, [ability](crates/mmorpg-core/tests/combat/abilities.rs), [mastery](crates/mmorpg-core/tests/combat/weapon_mastery.rs) and [progression](crates/mmorpg-core/tests/zone/progression_rules.rs) tests.

## Quests and world incidents

**Quest objective / credit**: [quest.rs](crates/mmorpg-core/src/quest.rs) owns typed objectives, logs, progress, rewards and completion. [Greyhaven quest catalogue](content/greyhaven/quests.json) and [loader](crates/mmorpg-core/src/content/greyhaven_vale/quests.rs) author the data; [NPC quest actions](crates/mmorpg-core/src/npc_quest.rs), construction, evidence and other specialized world modules supply outcomes. Preserve stable quest IDs, progress sources and once-only grants; [quest tests](crates/mmorpg-core/tests/zone/quests.rs), [incident receipts](crates/mmorpg-core/tests/content/incident_receipts.rs). Atlas 5.4, [starter zone](docs/STARTER_ZONE.md).

**Incident / route**: [routine.rs](crates/mmorpg-core/src/routine.rs) owns day/night NPC placement and route helpers; [cart.rs](crates/mmorpg-core/src/cart.rs) is the existing merchant journey, [crossing.rs](crates/mmorpg-core/src/crossing.rs) the quest-triggered ford cart, [supply.rs](crates/mmorpg-core/src/supply.rs) the hostile patrol, [raid.rs](crates/mmorpg-core/src/raid.rs) raids. These are distinct policies, not automatically interchangeable. Check existing route/credit primitives and zone lifecycle before new incidents (e.g. caravan #1215). Atlas 5.1/5.4; [merchant cart](crates/mmorpg-core/tests/content/merchant_cart.rs), [crossings](crates/mmorpg-core/tests/world/crossings.rs), [routines](crates/mmorpg-core/tests/zone/routines.rs); [zone lifecycle](docs/ZONE_LIFECYCLE.md).

## Clients, authority and recovery

**Shared client model**: [mmorpg-client-model](crates/mmorpg-client-model) owns common UI/control semantics (camera, mouse ownership, HUD, quests, impact cues, and the [Interact ladder](crates/mmorpg-client-model/src/interaction.rs) the native client, the browser and its touch button read, #1252); [mmorpg-presentation](crates/mmorpg-presentation) owns shared visual semantics. Native adapters and browser/WASM adapters may differ in I/O/rendering but should not redefine the same semantics. For example, [camera](crates/mmorpg-client-model/src/camera.rs) is already shared through [native](crates/mmorpg-client/src/camera.rs) and [WASM](crates/mmorpg-wasm/src/camera.rs). Before extracting another shared module, trace the consumers of the existing one. [Native guide](docs/NATIVE_CLIENT.md), [browser guide](docs/BROWSER_CLIENT.md), [parity tests](crates/mmorpg-client/tests/native_presentation_parity.rs).

**Zone / canonical snapshot / projection**: [core zone.rs](crates/mmorpg-core/src/zone.rs) coordinates one writer; [snapshot.rs](crates/mmorpg-core/src/snapshot.rs) is recoverable canonical state; [projection.rs](crates/mmorpg-core/src/projection.rs) is the player-visible view; [protocol](crates/mmorpg-protocol) encodes both. [Game server adapter](crates/mmorpg-game-server), [control plane](crates/mmorpg-control-plane), [characters](crates/mmorpg-characters), and external game-server keep existing authority, fencing and persistence boundaries. Local host and WASM use the real core. See [architecture](docs/ARCHITECTURE.md), [protocol](docs/PROTOCOL.md), [scenarios](docs/SCENARIOS.md), [dependency boundary test](crates/mmorpg-game-server/tests/dependency_boundary.rs).

**Extension rule:** locate the existing authoritative source, state/data, callers, and relevant test before proposing a new implementation; distinguish live production, intentional specialized/fallback or diagnostic paths, and incomplete integration. If retrieval is partial, report the uncertainty. Add/update task relationships when implementation ownership moves. Do not infer absence from an unsuccessful text search.
