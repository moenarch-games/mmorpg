# Run the browser client

`web/` is the GitHub Pages client. It runs the shared Rust zone simulation in the page as a **local single-player zone host** ([ADR 0002](adr/0002-browser-embeds-zone-simulation.md)): the `mmorpg-wasm` crate compiles `mmorpg-core` and `mmorpg-protocol` to WebAssembly and builds the same `ZoneSimulation` and content revision as `mmorpg-zone-host` (zone 1, Greyhaven Vale). There is one implementation of the movement and combat rules; the browser owns none. In a development or self-hosting setup the same page can instead join a real zone host ([online mode](#online-mode)). The Pages build stays local and single-player. How the browser presents the world is described in [the architecture's browser presentation](ARCHITECTURE.md#browser-presentation).

## Build and run

```sh
scripts/fetch-bundles.sh                          # from the repository root, once
cd web && bun install --frozen-lockfile && bun run dev
```

`bun test` runs the browser tests and `bun run build` writes the static page to `web/dist`.

Building the page or the native client first needs the asset-tooling bundles: `scripts/fetch-bundles.sh` downloads the rolling Ranger figure and equipment releases file by file (refreshing each file whose release digest changed), the rolling kit, prop, animal and sound releases, the `greyhaven-nature` trees and rocks pinned by the SHA-256 of their tar, and the immutable `greyhaven-inn-v1` inn into the ignored `web/public/` (re-running it keeps a download while its release is unchanged; rolling releases are read live and unpinned, so it refreshes them after an upload). CI restores these downloads from the Actions cache, keyed on each release's live identity (`scripts/ci-asset-cache.sh`), and the fetch script still compares every rolling release with the live one, so a stale or empty cache cannot change the result. The page and the native client both build from those downloads alone (#866); the native dev launcher fetches them automatically when a required bundle is missing. See [the shared Ranger loading path and browser example](RANGER_ASSETS.md).

Building the page uses the current stable Rust toolchain from `rust-toolchain.toml` (including the `wasm32-unknown-unknown` target) and the currently installed Bun. The build selects a `wasm-bindgen` CLI matching the Rust crate resolved in `Cargo.lock`: it uses a compatible system CLI, or automatically installs the matching executable into `target/tools/wasm-bindgen-cli/` without modifying the global installation. Run `cargo update -p wasm-bindgen` explicitly when advancing that dependency. `bun run build` and `bun run dev` first sync browser dependencies from the committed lockfile, then compile the module. `bun test` also compiles the module before its WASM tests. The generated bindings are ignored build output.

After `vite build`, `web/scripts/build-asset-cache.ts` writes `dist/asset-cache.json` (every static file's SHA-256) and the service worker `dist/sw.js` (#410): on return visits the built page reuses downloaded WASM, chunks and bundle files from Cache Storage while the deployed manifest still names their revision, revalidates pages and the manifest on every navigation, stores a download only when its bytes match, and falls back to the network when storage is unavailable. Open the page with `?reset-cache` to drop it. Update the Git checkout explicitly to build newer source; these scripts do not change source revisions or dependency pins.

`python3 scripts/smoke-browser.py` checks the built `web/dist` in real Chromium (needs Playwright).

## Playing

- **Enter World** joins the local zone and spawns the selected character; **Characters** in the game menu (**Menu** or Escape, #636) leaves it and removes the unit. A projection the strict decoder rejects fails closed: entry is refused, or the page leaves the world, and the reason appears under **Enter World**.
- **Bags** (or B) shows the 16 projected bag slots. Select a stack, set its quantity, then choose a destination; only the zone changes the items. Escape closes the panel before opening the game menu.
- **Character** (or C) shows the equipment slots with item names and stats, the Stamina/Strength/Agility/Intellect totals, health and damage range from the received projection. Select an equippable stack in Bags and choose **Equip**, or choose **Unequip** in the pane; the zone performs every swap and refusal. Bags and the character pane can be open together.
- **The inn** east of the spawn plaza is a walk-in building (#158): click its door, or press E (gamepad Start) within 2.5 m with no NPC selected, to open or close it for everyone; the roof and ceiling hide while you are inside. **Vendor** (or V) trades with Innkeeper Bram Tolliver behind the inn's bar: within 5 m it lists his priced stock with **Buy** and your bag with each stack's sale value and **Sell**. Only the zone moves copper and items; opening it closes Bags, Loot and the character pane.
- **Left-click (or tap) a visible creature or NPC** to select that specific unit (#636: selection never attacks; Q swings). Selection sends the zone-validated target intent. The closest drawn body under the pointer wins; solid scenery blocks picking hidden units. A camera drag, canceled pointer or click on empty ground does not select. A confirmed quest-NPC or vendor selection opens its dialogue or shop, showing reach feedback when needed. Guards and other NPCs remain selectable without invented dialogue.
- **Talk** (T, or the button in the quest log) opens the dialog of the selected quest NPC, or the nearest quest giver when no NPC is selected: the quests it offers (**Accept**), quests ready to turn in with their reward choice (**Complete quest**) and quests still in progress. Talk and Vendor never substitute another NPC for an explicit NPC selection. **Quests** (or L) shows the log with each objective's progress and **Abandon**; the HUD tracks every active objective, and `!` (available), `?` (ready) and grey `?` (in progress) float over quest givers. Givers need you within 5 m; only the zone accepts, credits and rewards quests. Start with Marshal Elden Greywatch west of the spawn plaza.
- **Chat**: Enter focuses the chat field (held movement stops while you type); Enter sends the line to players within 20 m, `/y` yells it to 60 m, Escape returns to the world. `/wave`, `/bow`, `/cheer`, `/laugh` and `/point` emote to players within 20 m. `/sit` sits on the ground, and E takes a chair or a bench place within 2.5 m; moving, jumping, damage, casting or attacking stands you up. You may speak or emote once per second; the zone delivers every line and emote, including your own, and they are not saved.
- **Loot** selects your current owned corpse, or the nearest visible owned corpse. Move within reach to see its projected copper/items, then choose **Claim rewards**. The HUD shows received copper; full bags retain corpse rewards. Bags and Loot open separately, and Escape closes the current panel before opening the game menu.
- **Movement and camera.** W/S run and backpedal, A/D always strafe, Space jumps (held to swim up in deep water; X swims down), and F rolls. Keys 1–9 and 0 use the action bar and Shift+1–0 its second row. Click the world to capture shooter-style mouse-look; wheel zooms. Left click selects at the centred crosshair while captured, or at the visible cursor when free. A living selected enemy smoothly takes over camera tracking and facing, releasing the cursor for HUD actions; a click on empty world clears focus. Q swings with or without focus; right click cancels a held strike or guard without firing, otherwise the cast. Escape (or a lost pointer lock) opens the game menu (Resume, Settings, Characters) once no panel is open. While a strike or guard is held, mouse motion aims it and the camera stays locked (Settings: "Camera during a strike or guard" locked or free, #636). Touch drag still turns the view. F3 shows rendering observations. The camera and aiming rules are in [controls](CONTROLS.md).
- **Bindings and Settings.** Keyboard and gamepad actions resolve through `input-bindings` (`web/src/input/game-controls.ts`, over the catalog the native client loads too, `content/settings/input-actions.json`, #1284), including the held Warden guard and directional Heroic Strike; blur, menus, Settings, remaps and hidden tabs retire held actions. Open panels let movement fall through, with text fields/Settings owning their keys. **Settings** uses the shared `settings` session and per-character `input-bindings` profiles for field of view, look sensitivity, inversion, accessibility and remaps. Settings pauses the local zone and blocks online input. The browser sends the zone command wire with strictly increasing sequences and movement resends.
- **Radial wheels (#653, off by default):** with Settings → Wheels on, hold T (fixed wheel, eight sectors chosen in Settings) or K (context wheel: the selected NPC's or target's actions), flick the mouse toward an action and release, or tap and left-click; right click cancels and the camera holds still. Both clients share the rules; see [controls](CONTROLS.md#radial-wheels-as-delivered-653).
- **Touch (#434):** on touch devices (coarse pointer, or any finger press; a mouse press switches back) the world shows touch controls and a compact landscape HUD. A left virtual thumbstick moves (eight directions), a finger drag elsewhere looks and turns, a pinch zooms and a tap selects. Four face buttons fire hotbar slots 1–4 (bottom, right, left, top); the centre modifier, then a face, fires slots 5–8, and a hint ring names what the next tap fires. Context buttons show Target and Attack near or with an opponent, Loot, Trade, Talk, Open or Repair in reach, and Release spirit when dead; Jump also swims up while held, and a Menu button opens bags, character, quests, chat, Settings and Characters. Chat collapses to a button, the toolbar folds into the menu, the minimap shrinks and the unit frames and action bar scale down. Every button fires the same semantic action as its key (`web/src/input/touch-layout.ts`), so the zone validates the same intents; the touch layout is not yet rebindable.
- **Sound (#447):** the page plays the native client's cue mapping (`mmorpg_presentation::audio`, exported as `UnitPresenter.takeAudio`) through the shared [game-audio](https://github.com/moritzbrantner/game-audio) wasm package on Web Audio, from asset-tooling's CC0 `combat-sounds` bundle (`web/public/sounds/combat-sounds`, fetched by `scripts/fetch-bundles.sh`). Audio unlocks on the first click, key or touch and suspends while the tab is hidden; Settings → Audio sets master, effects and interface volume and mute. Without Web Audio or the bundle the page is silent and every visual telegraph is unchanged ([native details](NATIVE_CLIENT.md#current-limits)).

### Combat

Tab or a left click selects; Q, gamepad X or the touch Attack pill swings where the character faces and hits everything in a 100° arc in reach, targeted or not (#517); 1–9 and 0 (or a click on the action bar) use the chosen class's abilities (offensive ones fire where the character faces, heals and buffs land on the selected friend or yourself; [held Aimed Shot and Piercing Shot draw the bow and fire on release](CONTROLS.md#hold-to-draw-power-shots-607)); a right click cancels a cast and R releases a dead spirit.

A Warden's **directed Heroic Strike** is a separate bindable action (default G): hold it, move the mouse left/right and up (high) or down (low), and release to swing; the zone resolves which creature the sweep physically reaches (or a whiff) and both clients show the accepted 0.3 s wind-up and 0.15 s sweep with fitted sword motion and a brief matching airborne trail ([timed combat](PVP_COMBAT.md#timed-swings-and-clashes-679-arena-first)). Blur, Settings, an open panel, the game menu, a right click, a stun or death cancel the held aim without a strike; the Heroic Strike slot shows the working binding as a compact hint and in its tooltip, or says it is unbound.

The Warden's **shield guard** is another bindable held action (default Z): hold it and move the pointer up (high) or down (low) to pick the lane; the zone blocks matching creature blows from the front and shield side, slows movement while the guard is up, suspends it in the air, and a heavy charging blow breaks it for 1.5 s before the held lane returns. A lane indicator beside the screen centre shows the zone's guard (steel while protecting, dim while suspended, red while broken), blocks and breaks flash at the lane and float Block / Guard broken text, and the most recent of guard and directed strike owns the pointer (pressing one cancels the other without a strike). A directed strike commits the Warden to a 0.2 s recovery: a guard pressed during it is held and protects as soon as the recovery ends.

Warden melee is **movement-dependent** (Atlas 5.2.69–5.2.70): charging at the target deals +20% melee damage, an airborne (overhead) blow +35% while the airborne Warden takes +25% creature melee damage, a planted Warden takes −10% and one backing or strafing away deals −15%; melee pressed during the short landing recovery waits and fires when it ends. The status line names the current stance. A directed Heroic Strike that damages a creature opens the Warden's first **combo**: Shield Bash pressed during the 0.2 s impact or the following 0.6 s window hits exactly that creature (whatever is selected) and may ignore only the slash's global cooldown; the status line announces the open combo.

The **action bar** (bottom centre) shows the class kit with keybinds and glyph icons; hover, right-click or long-press a slot for its tooltip (cost, range, cast time, cooldown, description). Slots tint blue without enough resource, turn the keybind red when the target is out of range, sweep radially over a cooldown (seconds from 2 s) or the global cooldown, highlight while casting and grey out with their unlock level until learned. The [browser Warden hotbar](WARDEN_ABILITY_ART.md) uses four owner-approved painted icons from asset-tooling. The **player frame** shows health, the class resource (rage red, focus amber, mana blue) and buff and debuff icons with time left; the **target frame** shows the target's health, auras and cast; a **cast bar** sits above the action bar (channels drain backwards, with an Interrupted flash). Floating **combat text** shows damage, heals (green), Absorb, smaller periodic damage and interrupts, and the status lines give readable messages for every error code. Names and numbers come from the module's `catalog()` export and the decoded projection; the range line comes from the catalog, and the descriptions in `web/src/world/units/ability-presentation.ts` are held to the core's ability definitions (`abilityFacts()`, `web/tests/core-facts.test.ts`). Reaches the interface uses as hints (loot, vendor, quest, gathering, raid steps) come from `zoneConstants()`; the zone checks every intent.

### What the page draws

- A `WorldSource` seam (`web/src/world/`) advances fixed 60 Hz ticks from a bounded accumulator and hands presentation only encoded player-scoped projections, decoded like the online source's by `mmorpg_protocol` itself through `mmorpg-wasm` (`web/src/replication.ts`, #541). Canonical state never reaches rendering. [Online mode](#online-mode) swaps in a WebTransport source behind the same seam.
- The world is drawn from the WASM module's `scenery()` export, which maps the same `mmorpg-scenery` Greyhaven Vale the native client draws: relief terrain in biome tones with smooth roads, plaza and shore, distant ranges softened by renderer fog, models for every prop with shared instance geometry for repeated trees, grass and rocks and static batches for structures, a translucent lake, and a renderer sky with a matching CSS backdrop. Structures' walls are their exact core colliders. Greyhaven's trees, bushes and rocks are asset-tooling's `greyhaven-nature` bundle (#49) in both clients, with distance-selected levels of detail that cross-fade at each switch; rocks collide as the bundle's authored convex proxies. A circular minimap shows the subzone name, roads, water, buildings and units.
- Ambient and directional lighting follow a cosmetic twenty-minute noon/dusk/night/dawn cycle; reduced motion holds noon. This clock never changes simulation or NPC behavior. Picking tests the actual rendered transforms. Spell visuals (a Firebolt projectile, Frost Nova ring, Arcane Barrier bubble, Blizzard shards, Ranger arrows and Warden swing arcs) are short-lived renderer nodes driven by projection events, and per-actor poses follow ordinary swing occurrences and accepted abilities, including creature casts. Confirmed positive damage produces bounded target-local impact sparks. Players and creatures fall on observed death, while newly hydrated corpses start settled; death overrides actions. Reduced motion snaps corpses and hides action/effect motion. Units stand at their physics position plus the shared relief.
- Players are asset-tooling's animated Ranger humanoid (Universal Base Characters with the Ranger outfit, CC0; Atlas 6.3.7, every class and sex alike until more character bundles exist), loaded with 3d-lab's bundle loader (a Warden carries the bundle's sword and shield through 3d-lab's attach API, and a standing Warden holding guard raises the shield with the `Idle_Shield_Loop` clip), and wolves, vermin and boars are animated Quaternius CC0 animals (Atlas 6.3.6), as in the native client; humanoid creatures and NPCs use procedural models. Ranger humanoids also use the bundle's authored takeoff, airborne and landing clips from the projected vertical-motion cue, shared by both clients; their roots remain at the projected body position. Imported models load on demand, with procedural low-poly models (quadruped animals with a trot, compact humanoids; unknown templates fall back to a box) shown while a model loads, with the disposition colour (hostile, neutral, friendly) as an accent that their minimap dots share; corpses lie down.

## Characters and saves

Each roster character is **durable** (Atlas 3.1.6): entering leases it from browser storage through the same `mmorpg-characters` record and lease rules zone hosts use, and its level, XP, copper, bags, equipment, quests, health, cooldowns and position are committed every five seconds, when the page is hidden and on leaving, then resumed on the next visit; the roster shows its committed level. One tab plays a character at a time (Web Locks); a reloaded page's newer local zone epoch fences the page it replaces. The world is saved beside them (Atlas 3.3.8): the local zone's checkpoint without players resumes on the next visit, one world per browser and one tab at a time; a saved world from another version is reset with a notice. There is no handoff, shared world or multiplayer authority, and browser storage is a development adapter. See [save and load](SAVE_LOAD.md).

The command and projection formats are identified by one random protocol ID ([ADR 0006](adr/0006-merge-safe-format-identities.md)); see [the wire specification](PROTOCOL.md).

## Online mode

The same page can join a real zone host instead of its local zone, over WebTransport with the `game-server` session protocol: the browser counterpart of the native client, and the transport swap [ADR 0002](adr/0002-browser-embeds-zone-simulation.md) kept open. It is a development and self-hosting mode; the GitHub Pages build stays offline.

```sh
./scripts/dev-browser-online.sh
```

The launcher reuses or creates the ECDSA P-256 development certificate under `target/dev-tls/` (valid for 10 days; WebTransport certificate hashes allow at most 14), starts `mmorpg-zone-host` for zone 1 on loopback (the `--lan` address with `--lan`), UDP port 4433 (status on TCP port 8080) and Vite on `127.0.0.1:5173`, and prints a URL to open in two tabs of a Chromium-based browser. Ctrl-C stops both processes, `--check` verifies the setup and exits, and `MMORPG_DEV_TRANSPORT_PORT`, `MMORPG_DEV_STATUS_PORT` and `MMORPG_DEV_WEB_PORT` override the ports. It shares the certificate and ports with `./scripts/dev-native.sh`, so run one of them at a time; a native client can join the launcher's zone with the [second-player command](NATIVE_CLIENT.md#interactive-play).

- **Selecting a host.** `?server=https://<host>:<port>/game/matches/zone-<id>&certHash=<base64 SHA-256 of the DER certificate>` joins that host; without `certHash` the host needs a publicly trusted certificate. A build with `VITE_ZONE_SERVER` and `VITE_ZONE_CERT_HASH` offers the same through a **Play online** checkbox on the character screen, unchecked by default; the default remains the local WASM zone. The address must be a canonical admission route: credentials, queries, fragments and resume routes are refused, and an invalid address disables entry with the reason instead of falling back to the local zone.
- **Session.** `OnlineZoneSource` (`web/src/world/online-zone-source.ts`) reads the welcome (player, tick rate, connection epoch, reconnect token), sends command frames with strictly increasing sequences, reassembles and verifies snapshot frames and fragments per connection (`web/src/session/`, a port of `game-server`'s `SnapshotReassembler`), and decodes projections with the same decoder as the local zone. Movement is held intent the page resends every 50 ms, like the native client; a jump or any other discrete intent is resent byte for byte until a projection acknowledges it, and no later command overtakes it meanwhile, so the host's stale-sequence rule cannot drop it unseen.
- **Fail closed.** Every projection must carry the page's zone, player and the content revision of the scenery the page loaded. A mismatch or a malformed frame leaves the world with the reason under **Enter World** rather than drawing a different world.
- **Interruptions.** A lost connection or five seconds without projections triggers one bounded resume with the in-memory token while the last scene stays visible and the top bar shows **Reconnecting…**; Characters (in the game menu) cancels it. The resume keeps the player and command sequencing, starts stopped until acknowledged, drops intents made meanwhile and resets interpolation for the new connection epoch. A refused or expired resume ends the session; a new player is never substituted. Tokens stay in memory: they never appear in the page URL or the page's messages (a browser's network console may still show a failed resume request).
- **Leaving.** Characters (in the game menu) or closing the tab ends the session; the host keeps the character for its reconnect grace (five seconds in the launcher), then removes it. Without character storage, sessions remain anonymous and choose class/sex with `ChooseClass`. With `MMORPG_CHARACTER_DIR`, the selected character instead claims its durable server record before entering; explicit Characters/Exit commits and releases it. Closing a tab abruptly retains its latest periodic commit. Appearance remains presentation-only.

`python3 scripts/smoke-browser-online.py` proves it end to end with the production bundle: it starts a real host with a disposable certificate on OS-selected ports, opens two Chromium pages in online mode, runs one character and checks the other page sees it move in its own decoded projections, then closes the running page and checks its unit disappears after the host's one-second grace.

### Play together on a local network

On the **host computer**, use its actual LAN IPv4 address (for example `192.168.1.20`):

```sh
./scripts/dev-browser-online.sh --lan 192.168.1.20
```

The launcher runs **one** authoritative Greyhaven zone host (UDP 4433) and serves the browser game over HTTPS on that LAN interface (TCP 5173). The printed link names the correct LAN WebTransport endpoint and its development certificate hash. Other computers on the same network open **that link** in a Chromium-based browser; they do not need the Rust toolchain or a copy of the game source. Each player selects **Enter World** to join the same zone. `--check` also works with `--lan` to verify server readiness and the HTTPS page before playing.

The page uses a self-signed **development** HTTPS certificate. On each device, trust the host's certificate `target/dev-tls/cert.pem` for this locally controlled server (or explicitly accept the browser's certificate warning where supported) before using the shared link. Never distribute `key.pem`. The launcher includes the LAN IP in the short-lived certificate's subject alternative names, regenerating the pair if the IP changes. Open firewall access for **TCP 5173** (HTTPS page) and **UDP 4433** (WebTransport) only to trusted LAN peers; do **not** forward the ports to the internet. The server has anonymous sessions and no public authentication or production durability.

You can also connect a **native client from another LAN computer** to this host (or to one running `./scripts/dev-native.sh`) by copying **only** the public certificate `cert.pem` to that computer and supplying its LAN endpoint:

```sh
cargo run --locked -p mmorpg-client -- \
  --url https://192.168.1.20:4433/game/matches/zone-1 \
  --certificate ./cert.pem
```

The ordinary `./scripts/dev-browser-online.sh` (without `--lan`) stays bound to loopback and uses HTTP for local development. The GitHub Pages demo remains local single-player.
